# Onboard GA4 and BigQuery

Use the selected Fusionmetrics Organization and the Partner's authorized Google and Shopify accounts. This workflow configures acquisition data; it does not use direct GA4 queries as a substitute for Fusionmetrics analytics. Read [browser setup](references/browser-setup.md) when creating or changing a property, tracking configuration, export link, or IAM grant.

Keep evidence for each stage separate: Shopify tracking, the GA4 property/stream, the daily Google export, BigQuery access, the saved Fusionmetrics mapping, and the completed import. A saved credential or successful import proves only the stages actually checked. Synthetic or manually populated BigQuery tables can validate the importer but cannot prove that Shopify tracking or GA4 export is configured. Label such data as synthetic and do not diagnose its fixed historical dates as a broken export. Report provider stages as unverified until observed. An empty revenue-attribution table requires checking matching and source data; do not promise it will populate merely with time.

1. Call ga4_get_status, optionally with the appKey from list_apps. Confirm the app, its existing mapping, saved credential, and import state. The response includes browser links and the managed service-account principal. If the server does not expose the GA4 tools yet, use the same controls in the linked Fusionmetrics browser settings and report the server-version limitation. Do not invent tool success.
2. Reuse the intended GA4 property/web stream and Google Cloud project, or prepare the exact creation choices for the Partner. Resolve the app's Partner account and Shopify app ID from Fusionmetrics metadata. Complete the authorized browser steps for Shopify tracking, the daily BigQuery export, and dataset access. The Partner enters Measurement Protocol secrets and any service-account JSON directly in the provider/browser form; do not read, copy, log, or screenshot those secrets.
3. Prefer Fusionmetrics' managed connection. Grant its exact returned principal BigQuery Data Viewer on the chosen dataset. Fusionmetrics handles read-session access in its own project. Managed connections do not enumerate datasets: get project and dataset IDs from the confirmed GA4 export link/BigQuery page. Use project.analytics_<property_id>, without a table suffix. If no managed principal is available, guide the Partner through the existing browser credential form and the uploaded-credential permissions in the reference.
4. Show the app, project.dataset, saved credential identity, and any mapping being replaced. Use existing authorization when it covers this exact change; otherwise obtain confirmation. Call ga4_configure_dataset with confirmed=true and a unique idempotencyKey only after authorization. This validates access and saves the mapping. Preserve the existing mapping when validation fails; inspect the error and fix the specific cause instead of changing to another app or dataset.
5. Inspect the validation result: daily table suffix, event counts, detected app slugs, read mode, and warnings. A missing install event is a reporting limitation, not proof that every acquisition import is unusable. A wrong app slug or incompatible event scope requires resolution before import. A new export with no daily tables is waiting for export, not complete; streaming/intraday tables do not satisfy the importer.
6. Start ga4_import_attribution after the validated mapping and import are authorized. Reuse the same idempotencyKey after an uncertain response. Poll ga4_get_status with the returned runId and appKey at least 15 seconds apart, inspecting trackedImport through terminal state. A queued run or an old watermark is not evidence that this import completed. Report the actual phase and imported table suffix; needsAttention directs the Partner to the returned settings link for the provider error, which this tool deliberately omits. Then use analytics describe_schema and a bounded acquisition query to verify prepared data is available; an empty table is not a successful attribution result by itself.

Use the host's approved browser with the Partner's signed-in session. When browser control is unavailable, provide the exact next UI step and continue through the MCP operations after the human completes it. Plugin installation does not grant Google billing/IAM authority. Before creating billable resources or granting access, identify the exact project, region, principal, role, and scope and ensure the Partner authorized that change. Never grant Owner/Editor as a shortcut.

Finish with the selected app, property/stream and project/dataset identifiers, granted principal/role, saved mapping, validation findings, import state/watermark, and any remaining human or export-wait step. Keep secrets and raw Merchant events out of the report. Google export creation has no historical-backfill guarantee.
